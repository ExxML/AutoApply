# AutoApply — Decisions

Choices made where PROMPT.md was silent or where the environment forced a deviation. Product name is **AutoApply**; the in-page host element is `<autoapply-root>`.

## Seed (Appendix D)

- Gemini via raw REST `generateContent`. No SDK, for full control of rotation.
- Claude (for Claude Pro/Max users without an API key) runs the user's own `claude -p` through a Chrome native messaging host (`src/native`), one host launch per call. Anthropic's terms forbid third-party apps from offering Claude.ai login or using subscription OAuth tokens, but allow a user's own sign-in to the unmodified Claude Code binary, so AutoApply never touches a token, and claude.ai cookies or the OAuth client are out. `--bare` would start faster but ignores subscription logins; `--safe-mode` keeps the login and drops the user's hooks, plugins, MCP and CLAUDE.md. The host hard-codes `--tools ""`, `--strict-mcp-config` and `--no-session-persistence`, and the extension can pass only the prompt, system prompt, and a model/effort matching `[a-z0-9.-]` (job pages are untrusted input). The schema goes into the prompt rather than `--json-schema` (that adds a tool turn), with zod validating as for Gemini. The model list is Claude Code's own (its stream-json `initialize` reply, which asks nothing of the model), fetched like Gemini's so new models need no extension update; a bridge installed before that refuses the request, and the built-in aliases stay until setup is run again.
- Model "added" order is tracked locally via `firstSeenAt`, because the API exposes no timestamp.
- No per-site adapters. A generic engine plus class-name heuristics only.
- Required consents are auto-accepted and optional consents auto-declined by default. Essays are drafted by default. Never submit.

## Toolchain

- Versions checked on npm on 2026-10-14: Vite 8.3, @crxjs/vite-plugin 2.7.1 (v2.x per §3.1; its peer range includes Vite 8 and it builds cleanly, so the two-config fallback was **not** needed), Preact 10.29, pdfjs-dist 6.4, zod 4.6, Vitest 5.0, Playwright 1.64.
- TypeScript is pinned to `~6.0` because `typescript-eslint` 8.x supports `<6.1`; TS 7 would break `npm run lint`.
- Preact 10 instead of 11: `@preact/preset-vite`/prefresh target Preact 10.
- `manifest.config.ts` passes the content script entry through a non-literal object because the CRXJS manifest type does not declare `match_origin_as_fallback` (the key is emitted unchanged).
- The content script is a CRXJS `standaloneFiles` IIFE, not the default module loader. The loader `import()`s the bundle through the page's fetch context, so a page's `Connection-Allowlist` header (YouTube sends it report-only: console error "Unsafe attempt to load URL chrome-extension://…" in the extension's Errors list) flags it, and an enforced one blocks it, so the script would never load.
- Icons are generated by `scripts/make-icons.mjs` and committed under `public/icons/`.

## Storage

- zod 4 removed `.deepPartial()`. Every profile/settings leaf has a `.catch(default)` instead, so parsing a partial or partly invalid object yields a full object with defaults; this replaces `ProfileSchema.deepPartial()` for §10.9 and makes all storage reads tolerant leaf-by-leaf.
- Content scripts never access `chrome.storage` at all (strongest form of §18.5). Everything they need comes from `GET_RUNTIME_CONFIG`; the few writes they need go through messages (`SET_OVERLAY_POS`, `LEARNED_USED`). `storage.ts` has a per-context allow-list (`background`, `options`, `popup`); the popup cannot read `apiKeys` and gets key health from `TAB_STATUS`.
- Overlay position per host is stored in an extra local key `overlayPos: Record<host, number>`.

## Messages (additions to §17)

- `MAP_FIELDS` / `CHOOSE_OPTIONS` / `DRAFT_ESSAYS` carry a `groupId` (one per pipeline run); `ABORT {groupId}` cancels exactly those fetches.
- `LEARNED_USED {ids}` updates `learnedAnswers[].lastUsedAt` after a Phase-A learned-answer fill.
- `BROADCAST_FILL {rerun}` lets the top-frame overlay (Re-run, Retry) trigger every frame of the tab.
- Options page → background: `ADD_KEY`, `TEST_KEY`, `REFRESH_MODELS`, `VALIDATE_MODEL`, `PARSE_RESUME`, so all network calls stay in the background (§4).
- The popup's **Fill this page** and the Alt+Shift+F command send `TRIGGER_FILL {force:true}` to **all frames** of the tab (not only frame 0), so forms inside iframes are filled too; frames without fields do nothing.

## Build

- **Service-worker entry `src/background/sw.ts`** (one line: `import "./index"`). With CRXJS 2.7 on Vite 8 (Rolldown), two emitted entry chunks named `index.ts` (background and content) were resolved to the same file, so the service-worker loader imported the _content_ bundle. Giving the worker entry a different basename fixes it; `src/background/index.ts` still holds all background code as laid out in §3.5. The manifest's `background.service_worker` therefore points at `src/background/sw.ts`.
- Content-script bundle: ~84 KB minified in total (entry + shared chunks, no Preact/pdf.js/zod), under the 120 KB budget (§19).
- pdf.js 6 never uses `eval`/`new Function` (the old `isEvalSupported` option no longer exists); its worker is bundled and loaded via `?url`.

## Scanning

- **Field container (§11.5 step 5)**: climb up to 4 ancestors from the control (or a group's common ancestor) for as long as the ancestor contains no other field; the highest such ancestor is the container. This is the "field wrapper" whose preceding text is the label and whose box is badged. Climbing stops at `<form>`/`<body>`.
- Label regexes use word boundaries for `state|province|region` and `apt|suite|unit|town` so "Personal statement" or "Business unit" do not match.
- Checkbox `fieldset`/`[role=group]` grouping applies only when the boxes share a `name` (or have none); differently-named boxes in one fieldset stay separate fields (they are submitted as separate values, e.g. several consent boxes).
- Cookie-banner exclusion (`/cookie|consent-banner|onetrust|gdpr/`) applies only to controls outside any `<form>`, so a form's own GDPR consent section is not dropped.
- `<header>` fields are skipped only when they are not inside a form; `nav`, `[role=navigation]` and `[role=search]` are always skipped.
- Password, search and CAPTCHA/honeypot fields are skipped entirely (not listed). Payment and government-ID fields are listed and flagged "Sensitive – fill manually" (§18.2).
- Radios/checkboxes that are visually hidden count as visible when their `<label>` is visible (custom-styled controls).
- Button-style groups made of plain `<button>`s require: 2–8 siblings, none submitting (explicit `type="button"` inside forms), short texts not matching navigation words, and a container label ending in "?".
- The C.3 heuristic `button[aria-expanded][aria-controls]` is used only when its container's label is a question.
- A dropdown trigger wrapping more than one native control is not treated as a single dropdown (protects against broad `[data-testid*=select]` matches).

## Pipeline

- Résumé/CV and cover-letter **file** fields are resolved in Phase A without AI (primary résumé / a `cover_letter` document, else flagged). Other file fields go to the AI for a `documentId`.
- Consent checkboxes matching the §14.8 regex are decided locally before any AI call; the AI's `consent` action is handled the same way.
- Consents to AI tools assessing the application (ADI's Yes/No) follow the profile's **Consent to AI review of application** without an AI call, like interview-recording opt-ins. Unset leaves them to the consent settings and the AI, as before.
- Pre-harvesting dropdown options uses a 400 ms budget per dropdown; a list not fully collected in time (e.g. a long virtualized list, or an infinite-scroll list still loading pages) is not stored. A scrollable list counts as complete only once it stays quiet at the bottom for 0.5 s (no growth, no visible spinner); the budget cannot cut that wait, so a complete scrollable list costs up to 0.5 s more, and a visible spinner extends it (up to 5 s per page). Lists of 500+ options are never stored. Filling such a dropdown first tries to find the intended answer as an exact option directly (scrolling a virtualized list until found), then harvests fully and uses `localMatch` → `chooseOptions`.
- Waits after scrolling a list also wait for two animation frames (virtualized lists re-render from scroll events) but never more than 100 ms, so background tabs cannot hang a fill.
- `MAX_TOKENS` throws immediately so the mapping service splits the chunk; invalid JSON / schema mismatches are retried once (on another key via LRU), then on the fallback model, then the chunk is split, and a single failing field is flagged.
- After a capability error the retry prefers the same key.
- A user's trusted `input` on a field marks it user-owned (never filled afterwards). `keydown` is not used, so tabbing through fields does not claim them.
- **No automatic filling.** A fill runs only when the user triggers it (popup, Alt+Shift+F, the overlay's Re-run/Retry, or the rate-limit auto-retry of that run). Until then the content script only loads its config and listens for messages and user edits: no page scoring, no scanning, no `MutationObserver`. Fields revealed after a fill, and the next step of a multi-step form, need another trigger.
- The popup's **Fill this page** and a top-frame **Re-run** re-process flagged/failed/"check" fields as well as new ones; filled and user-owned fields are left alone.
- Learned answers' `lastUsedAt` is updated through an extra `LEARNED_USED` message.

## UI

- Badge tooltips use the native `title` attribute on the pill. For essays, "Save as reusable answer" is offered by clicking the purple pill (a native tooltip cannot hold a link); it opens the same learning card.
- The overlay's vertical position is stored per host as a bottom offset (`overlayPos`).
- Setup-wizard progress lives in the URL (`#/setup/1…4`), so steps can be skipped and resumed; a step shows ✓ when done.
- "Reset everything" uses an inline three-click confirmation instead of browser dialogs.
- Only PDFs can be the primary résumé (text extraction is PDF-only); DOCX/TXT files can still be uploaded and attached.
- The popup shows "Ready" when at least one key and a model are configured, otherwise "Setup needed".
- Model "New" badge: first seen within 7 days **and** later than the earliest `firstSeenAt` in the catalog (i.e. it appeared in a later fetch).

## Tests

- End-to-end tests run Playwright's bundled Chromium with `channel: "chromium"` and `headless: true` (the new headless mode loads extensions), on Windows without xvfb. `context.route` also intercepts the extension service worker's `fetch`, which is how the Gemini mock is applied.
- The test fixture closes the install-time setup tab before opening the test page, so the page is in the foreground (background tabs get no animation frames).
- Fixtures are served under `/jobs/…` on ports 5501/5502; the second port makes `iframe-form.html` cross-origin.
- The mock decides by field label (a stand-in for the model's semantic judgement); the real semantic behaviour is covered by `npm run test:live`.
- `chrome://extensions` "no errors or warnings" is checked on the extension card in developer mode after a full fill (Chrome renders the Errors button and warnings only when present).

## YOLO mode

- **Off means off.** Nothing YOLO runs until it is switched on: no alarm, offscreen document, DNR rule or tab listener exists. The content script's only cost is one `location.ancestorOrigins` read at bootstrap (and ~15 KB more bundle: 104 → 119 KB, under the 120 KB budget). Submissions after a manual fill are noticed only through listeners `listen()` adds at the first fill.
- **Hidden host.** Applications run in an iframe of an offscreen document (`IFRAME_SCRIPTING`), one at a time, closed when the queue empties. Verified 2026-10-26 on Workday, Greenhouse, Lever, Ashby, Oracle HCM, SmartRecruiters, iCIMS, SuccessFactors, Eightfold and Indeed's results. A DNR session rule (`tabIds: [TAB_ID_NONE]`, `sub_frame`) removes `X-Frame-Options`/CSP while the host is open. Pages refusing to work hidden (bot wall, no driver hello in 45 s) are retried in an inactive tab in a collapsed "AutoApply" group.
- **Throttling.** The host's frames report `document.hidden === false`, yet Chrome renders no frames there and wakes timers once a second. `throttled()` (`content/yolo/frame.ts`) sends them down the hidden-tab paths: SW-timed `sleep`, no rAF waits, synthetic scroll events, and `pageTimers.ts` rerouting the page's short timers while a run works.
- **A page that never renders**, found live 2026-10-26. `pageTimers.ts` (MAIN world, host frames only) stands in for rendering:
  - idle callbacks run on a timer, since Remix hydrates from one; Greenhouse's job boards otherwise never got their event handlers;
  - animation frames run on a 16 ms timer;
  - Resize/IntersectionObservers measure on `observe` and after DOM changes.

  The driver also switches CSS transitions off, since a menu fading in stays at opacity 0 (Workday's dropdowns).

- **One driver frame.** The host's own frame drives (`ancestorOrigins.length === 1`). An application embedded in a company page is loaded on its own instead (its iframe's `src`). Tab hosts are told by `YOLO_ATTACH`. A popup (`window.open`, `target=_blank`) loads in the same frame.
- **Run state** lives in `chrome.storage.session` (`yoloRun`), so a service-worker restart mid-application loses nothing. Each new document's driver says `YOLO_HELLO` and continues. Loop guard: the same step signature 3 times, or 40 steps.
- **Pages are classified in the background.** The driver sends `PageFacts` (text start, headings, alerts, counts, controls found) with each step; `background/yolo/classify.ts` holds the wording tests, keeping them out of the content bundle.
- **Nothing left blank.** With `yolo`, `mapFields` runs as usual and then sends every still-flagged _required_ field to one `BEST_GUESS_PROMPT` call, which sees why each was flagged and any earlier guess. Optional fields stay empty rather than guessed, and so do choices whose options read blank. Profile guards (sponsorship by country, wrong-site links) still apply to the guesses. Guesses are badged "Check", cite `["guess"]`, and are logged per application. AI-use attestations are answered as a human applicant would (the user's choice). Required government-ID/payment fields end the run ("Needs you"); they are never made up. A required cover-letter upload with none on file gets a drafted letter as a text PDF (`yolo/pdf.ts`).
- **CAPTCHAs are never attempted.** A visible challenge (never the invisible score badge) pauses the job as "Needs you" with a desktop notification. Clicking it (or Resume) reopens the job in a visible tab, where the run waits for the user and goes on.
- **Discovery.** GitHub feeds (SimplifyJobs `listings.json` or README tables) use conditional requests. LinkedIn's logged-out search is fetched without cookies; its postings are applied to on the employer's ATS board, found by company slug (`findOnEmployerBoard`), since logged-out pages hide the apply link. Glassdoor is parsed from its HTML. Indeed's results are rendered in the host. Career sites use their ATS's public API (Workday CXS, Greenhouse, Lever, Ashby, SmartRecruiters), else their rendered job links. Rejected postings aren't marked seen, so changed filters see them again. Easy Apply listings are skipped for now (`easyApply` flag).
- **Duplicates.** One `applications` record per canonical job key (`yolo/jobKey.ts`: ATS + id, e.g. `workday:<tenant>:<req>` across a requisition's location copies, `greenhouse:<id>` for both `gh_jid` pages and boards), plus a fuzzy company|title|city key. Any YOLO attempt blocks another; the user's own submission blocks YOLO unless re-applying is allowed.
- **Accounts.** Passwords are random (18 chars, all classes), saved before sign-up is submitted, and AES-GCM encrypted with a non-extractable key in IndexedDB. Not exported; "Reset everything" deletes the key. Gmail (read-only) uses `launchWebAuthFlow`'s implicit flow, so any Google account works. Silent renewal, else a "Reconnect Gmail" notification.
- **Testing hook.** A build with `VITE_YOLO_DRY=1` stops before the final submit and reports every field's value; normal builds compile it out.
